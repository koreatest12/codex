# 2027~2029 정보보안기사 개념 심화·실무 학습 확장

> 학습용 독립 보완 자료 · 2026-10-31 · 공식 교재/기출/정답 아님. 본문 설명과 문제는 자체 작성이며, 원문 세세항목별 충족률을 주장하지 않는다. 응시 연도의 [KCA 출제기준](https://www.cq.or.kr/qh_cusgm10_001.do)과 [과목별 대응표](2027_EXAM_CROSSWALK.md)를 함께 본다.

## 0. 120개 신규 문제의 위치와 사용법

- **필기 100개**: 시스템·네트워크·어플리케이션·정보보안 일반·관리 및 법규별 **20개**의 직접 제작 개념 식별 연습. 실제 시험의 과목별 문항 수와 형태가 유사하다고 주장하지 않는다.
- **실기 20개**: 대응책·원리·계산을 직접 설명하는 **서술형 자체 연습**으로 자동 정답 판정 불가.
- 문제 파일: [security-exam-2027.json](../../data/study/security-exam-2027.json). **출처는 참고 URL**, 실제 기출 근거로 사용하는 URL이 아니다.
- 교재 활용 순서: [기초 6주제](DIGITAL_SYSTEMS.md) → [2027 대응표](2027_EXAM_CROSSWALK.md) → [심화 보안 개념](2027_ADVANCED_SECURITY.md) → 본 문서 → [실기 워크북](2027_PRACTICAL_WORKBOOK.md) → 초안 문제 직접 검토/승인.
- 대량 반영 방법: [2027 문제은행 가져오기](2027_BULK_QUESTION_IMPORT.md). DB/웹사이트에 자동 공개하지 않는다.

## 1. 시스템 보안: 한 번에 연결해서 이해하기

### 1-1. 인증·인가·감사

- **인증(Authentication)**: 접속자가 주장하는 신원이나 기기의 자격을 검증. **인가(Authorization)**: 인증된 주체가 특정 자원에 허용된 동작을 할 수 있는지 판단. **감사(Audit)**: 누가 어떤 정책 판단을 거쳐 언제 무엇을 했는지 추적.
- DAC(소유자 재량), MAC(강제등급 정책), RBAC(역할별 정책), ABAC(사용자·자원·환경 속성별 정책)를 혼동하지 않는다.
- **가상 사례**: 개발자 A에게 DB 조회는 허용하지만 계정 생성은 거부한다. 인증 성공은 A의 신원을 확인한 것이고, 계정 생성 403은 별도의 인가 결과이다. 로그는 요청 ID·시각·주체·객체·정책 버전을 연결해야 한다.

### 1-2. OS 보호기법

| 보호기법 | 무엇을 하는가 | 무엇을 보장하지 않는가 |
|---|---|---|
| DEP/NX | 실행 금지 영역에서의 코드 실행 방지 | 메모리 손상의 원천 제거 |
| ASLR | 특정 메모리 영역의 주소 예측 난이도 높임 | 모든 정보노출/제어흐름 변조 방지 |
| 최소권한 | 권한 오남용·침해 영향 범위 축소 | 부여된 최소권한의 악용 방지 |
| 감사로그 | 이벤트 추적·사후 분석 지원 | 침해 자동 차단·로그 조작 불가능 보장 |

**자체 확인문제:** DEP 적용만으로 입력 길이 검증을 생략할 수 있는가? → 아니다. 여러 보호기법의 적용과 취약한 코드 개선은 별도다.

### 1-3. 클라우드·컨테이너

가상머신은 일반적으로 게스트 커널을 갖지만 컨테이너는 호스트 커널을 공유한다. 컨테이너 이미지를 업데이트해도 특권 실행·과도한 볼륨 마운트·노출된 서비스 권한은 남을 수 있다. Trivy 이미지/설정 스캔과 ScoutSuite 클라우드 구성 감사를 **서로 보완하는 점검**으로 사용한다.

**가상 점검 예시:** `USER root` Dockerfile 발견→실제 요구 권한 파악→비root 사용자·권한 축소를 테스트→서비스 기능/실행 결과 재점검. 'root' 문자열 하나만으로 원격 침해 확정이라는 결론은 내리지 않는다.

### 1-4. 보안로그와 메타데이터

원본 로그에는 UTC와 로컬 시간의 차이가 있다. `2027-01-01 21:00:00+09:00`은 `2027-01-01 12:00:00Z`이다. 일관된 기준으로 시간 정규화한 뒤 사건을 상관한다. 클라우드 메타데이터의 일시 자격증명은 SSRF·과권한과 결합하면 위험하므로 메타데이터 접근 정책·인스턴스 역할 범위를 제한한다.

## 2. 네트워크 보안: 트래픽 한 흐름의 통제

### 2-1. 계층·주소·서브넷

`192.0.2.0/27`은 전체 (2^{32-27}=32) 주소, 일반적인 호스트 할당 수 30, 브로드캐스트 `192.0.2.31`이다. /31·/32의 특수 용도는 별도 검토한다. ARP는 같은 링크의 IPv4→MAC 주소 대응, DNS는 이름의 리소스 레코드 조회, NAT는 주소 변환이지 암호화가 아니다.

### 2-2. 라우팅과 정책의 독립성

라우팅에 목적지 경로가 있어도 방화벽·SG·NACL·OS 정책이 모두 허용한다는 뜻은 아니다. VLAN은 L2 브로드캐스트 도메인을 분리할 뿐, VLAN 간 라우팅 설정이 있으면 통신할 수 있다.

**자체 예제:** 인터넷 공개 HTTPS 웹서버와 사설 DB를 구성한다. 웹 443은 필요 범위에 허용, DB 5432는 애플리케이션 SG에서만 허용, 관리 SSH는 제한된 관리망만 허용한다. 공개 IP, 라우트 테이블, NACL, SG, 호스트 서비스 인증을 **각자** 확인한다.

### 2-3. 관제 장비

IDS는 탐지, IPS는 트래픽 경로상 차단을 수행할 수 있고, WAF는 HTTP 요청의 정책 검사에 중점을 둔다. NAC는 접속 정책을 집행한다. EDR/EPP는 단말 영역에 더 가까우며 XDR은 서로 다른 보안 도메인의 관측 자료를 연계할 수 있다.

### 2-4. 제로 트러스트

NIST SP 800-207은 위치만으로 자원을 신뢰하지 않는 접근을 제시한다. **ZTNA**는 자원별 접근 집행에, **SASE**는 네트워크 연결과 서비스형 보안 기능의 조합에, **XDR**은 연계된 탐지·대응에 초점을 둔다. '제품 세 개 구매 = 제로 트러스트 완료'는 잘못된 이해다.

## 3. 어플리케이션 보안: 입력보다 권한을 먼저

### 3-1. 세 가지 인가 실패를 정확히 나누기

- **BOLA(API1)**: 특정 문서 **객체**를 누가 읽을 수 있는가.
- **BOPLA(API3)**: 그 문서 중 `owner_id`, `isAdmin` 같은 **속성**을 누가 수정할 수 있는가.
- **BFLA(API5)**: 사용자 생성·삭제 같은 **기능**을 누가 실행할 수 있는가.

**자체 예제:** API 응답에서 자신의 문서는 조회 가능하지만 타인의 문서는 403, 관리자 경로는 403, 민감속성 수정은 스키마·정책에서 차단해야 한다. 상태코드 403/404 선택 자체보다 **서버 측 최종 권한 판단**이 핵심이다. [OWASP API Top 10:2023](https://api-security.owasp.org/editions/2023/en/0x11-t10/).

### 3-2. 웹 입력 및 세션 통제

SQLi는 매개변수화 쿼리, XSS는 출력 위치별 인코딩, CSRF는 토큰·SameSite·출처 검증, SSRF는 목적지/네트워크 제한이 주된 방어 방향이다. 각각을 혼동하면 설계 결함을 놓친다. CORS는 브라우저 교차 출처 접근 정책이지 사용자 인가 도구가 아니다.

### 3-3. OAuth 2.0/OIDC/JWT

OAuth2는 권한 위임, OIDC는 인증 계층. ID Token은 인증 정보, Access Token은 리소스 접근 목적. JWT를 Base64URL로 **디코딩**하는 것은 서명·aud·iss·exp를 **검증**한 것이 아니다.

### 3-4. 소프트웨어 공급망

SAST는 정적 코드 분석, DAST는 실행 중인 앱 점검, SCA는 외부 의존성 구성요소·취약점 관리를 지원한다. SBOM은 구성요소 목록으로 관련 추적을 돕지만 소프트웨어가 취약하지 않다는 인증서가 아니다.

## 4. 정보보안 일반: 암호 기술 선택

| 문제 | 맞는 기능 | 왜 다른 기술로 대체할 수 없는가 |
|---|---|---|
| 저장 데이터 기밀성과 위변조 탐지 | AES-GCM 등 인증 암호화 | 해시만으로 원문 비밀 보장 불가 |
| 메시지 송신자 신뢰·무결성 | 전자서명 | 서명만으로 원문 비밀 보장 불가 |
| 메시지 공유키 무결성 | HMAC | 암호화와 기능이 다름 |
| 양자 위협을 고려한 공유 비밀 설정 | ML-KEM (FIPS 203) | ML-DSA는 서명 표준 |
| 양자내성 서명 | ML-DSA(FIPS 204), SLH-DSA(FIPS 205) | KEM은 서명 기능을 제공하지 않음 |
| 암호문 상태에서 특정 통계 계산 | 동형암호 | 지원 연산/성능에 제약 |
| 자원 제한된 센서의 보호 | Ascon 등 표준 경량암호 | '경량'은 키를 짧게 해도 된다는 의미가 아님 |

**자가문제:** 해시함수, HMAC, 전자서명이 각각 비밀키를 필요로 하는가? → 일반 해시 자체에는 필수 아님, HMAC은 공유 비밀키를 필요로 함, 비대칭 전자서명은 서명자의 개인키가 필요하다.

비밀번호는 평문 SHA-256보다 전용 비밀번호 해싱/KDF 정책을 따르고, AES-GCM에서는 키/nonce 재사용 규칙을 숙지한다.

## 5. 정보보안 관리 및 법규: 위험을 운영 계획으로

### 5-1. 자산 → 위협 → 취약점 → 위험

'외부 공개된 SSH 관리 포트'는 노출/구성 문제라는 **증거**다. 이 노출이 곧 관리자 계정 탈취를 뜻하지 않는다. 위험도는 가능성과 영향, 자산의 중요도 및 기존 통제를 고려한다.

### 5-2. 계산 예시

자산가치 5,000만 원, 노출계수 0.4, 연간 사건빈도 0.1회라고 가정하면 SLE=5,000만×0.4=2,000만 원, ALE=2,000만×0.1=**연 200만 원**이다. 이 계산은 가상의 위험 정량평가이며 시험기관이 항상 같은 수치를 정한다고 주장하지 않는다.

### 5-3. BIA/BCP/DRP

BIA는 영향 분석, BCP는 업무 연속성 계획, DRP는 기술 복구 계획으로 이해한다. RTO(복구까지의 목표 시간)와 RPO(허용할 데이터 손실 시점)는 달라서 복구 우선순위와 백업 주기에 각각 연결한다.

### 5-4. 법규와 윤리

개인정보의 수집·보유·파기, 정보보호 관리체계, 클라우드 보안 제도 등은 **응시일 기준 최신 법률·시행령·고시·공식 안내**를 별도 확인한다. 이 문서는 법률상 신고기한·금액·신고 대상 여부를 확정하지 않는다. 실제 시스템 점검은 사전 승인·최소 범위·로그 비식별화 원칙을 적용한다. [국가법령정보센터](https://www.law.go.kr), [KCA](https://www.cq.or.kr/qh_cusgm10_001.do).

## 6. 실기 답안 구성과 복습

자체 사례마다 다음을 5줄로 써본다.

1. **자산/정상 동작** — 무엇을 보호하는가?
2. **관찰된 증거** — 로그·설정 등으로 확인된 사실은?
3. **취약점·위험의 가설** — 추가 확인할 사항은?
4. **통제와 조치** — 설정·개발·운영에서 어떻게 바꿀 것인가?
5. **검증과 책임** — 재점검 지표·담당자·기한·잔여 위험은?

**검토 원칙:** 문제 120개가 모두 공식 출제범위를 완전하게 대표한다는 의미는 아니다. 최종 사용자 검토 전에는 **전부 draft**이며 실제 공개 모의시험에 출제되지 않는다.
